# AGENTS.md

## Назначение репозитория

Это Python-бот для Polymarket — stateful execution plane централизованной
системы управления. Admin Panel — единственный control plane: она управляет
множеством изолированных экземпляров бота, их конфигурациями и активацией.

Один запущенный экземпляр бота работает только с одним аккаунтом Polymarket.
На одном сервере (и IP) работает только один экземпляр бота. Для нескольких
аккаунтов используются отдельные изолированные серверы/экземпляры.

Бот не повторяет функции Admin Panel. Панель определяет, **что** и с какими
параметрами требуется сделать; бот определяет, **как** выполнить это в рамках
торговой и доменной логики.

## Модель работы бота

Бот хранит runtime-состояние в оперативной памяти, в переменных процесса, ради
скорости: позиции, активные ордера, состояние стратегий, полученную
конфигурацию и другие объекты доменной модели. Не меняй эту модель на
постоянное хранение и не добавляй его без явного решения пользователя.

`.env` и другие локальные конфигурационные файлы не используются. При старте
CLI-флаги передают только минимальную bootstrap-конфигурацию для подключения к
инструменту связи (например, NATS). Рабочую runtime-конфигурацию и инструкции
бот получает из Admin Panel.

Последовательность запуска обязательна:

```text
CLI bootstrap → инициализация transport → подключение к Control Plane
→ регистрация bot instance → получение runtime-конфигурации
→ валидация и инициализация → активация Admin Panel → торговая логика
```

До получения и успешной валидации конфигурации, а также до активации Admin
Panel, торговая логика не запускается.

## Граница ответственности: Admin Panel и внешние инструменты

ИИ работает исключительно над ботом и не реализует, не проектирует, не
проверяет и не предполагает изменений в Admin Panel или иных внешних
инструментах.

Admin Panel считается уже готовым и независимым control plane:

- она принимает сообщения, события и результаты выполнения, отправляемые ботом;
- она умеет обрабатывать эти сообщения на своей стороне;
- она передаёт боту команды, runtime-конфигурацию и сигналы активации;
- внутренняя реализация, протоколы обработки и функциональность Admin Panel
  находятся вне области ответственности бота и ИИ.

Бот обязан корректно обрабатывать входящие сообщения согласно своему
контракту, но не должен требовать реализации Admin Panel для разработки и
тестирования. Допускается эмулировать Control Plane вручную, например
публикуя команды через NATS CLI.

При проектировании ИИ концентрируется только на доменной и прикладной логике
бота, его входных/выходных контрактах и надёжности взаимодействия. Не
добавляй в репозиторий функциональность, предназначенную для Admin Panel,
эмуляторы её бизнес-логики или предположения о её внутреннем устройстве.

## Работа с пользователем и изменениями

Не выполняй команды в терминале и не изменяй существующие файлы без
предварительного явного разрешения пользователя. Сначала сообщи:

1. зачем требуется действие;
2. какие именно файлы или команды оно затрагивает;
3. полный предполагаемый diff изменений.

После этого дождись явного согласия. Не считай молчание согласием.

Не создавай и не удаляй файлы без отдельного согласия. Перед созданием объясни
зачем нужен файл, предложи конкретное имя и спроси, устраивает ли оно
пользователя. Удаление также требует назвать точные цели и дождаться
подтверждения. ИИ не выполняет самостоятельно никакие действия с Git
(включая чтение статуса и истории, создание и изменение веток, добавление,
удаление и откат изменений, commit, amend, push, pull, merge и rebase).
Если пользователь явно попросил выполнить конкретное действие с Git, его
разрешение считается полученным только для этого действия и его необходимого
непосредственного контекста. Если действие с Git не было явно запрошено
пользователем, но требуется ИИ, ИИ сначала объясняет, зачем оно нужно,
называет точную команду или набор команд и ждёт явного разрешения.

Чтение файлов и диагностика тоже требуют предварительного разрешения, потому
что для них используется терминал. Если пользователь уже явно разрешил
конкретное действие в текущем сообщении, повторно разрешение не запрашивай, но
не расширяй его область.

## Подход к решениям

Не принимай предложение пользователя автоматически. Сначала проверь его на
корректность, риски, совместимость с этой архитектурой и возможное ухудшение
кода. Если для задачи есть более подходящий паттерн или несколько разумных
вариантов, прямо объясни разницу и предложи лучший вариант до внесения
изменений.

Отвечай по существу, прямолинейно и кратко: без приветствий, извинений,
повторения вопроса, лести и формальной вежливости. Не скрывай риски и не
соглашайся с решением, которое ухудшает архитектуру.
